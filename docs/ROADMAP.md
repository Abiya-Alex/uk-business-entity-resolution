# 30-day ticket backlog
| Days | Ticket | Acceptance criteria |
|---|---|---|
| 1–2 | SDE-001 Setup | Local run and CI green, understand problem document |
| 3–5 | SDE-002 Data | Download, convert, profile regional real data |
| 6–8 | SDE-003 Matching | Explain normalization, blocking, scoring and complexity; add edge tests |
| 9–12 | SDE-004 Evaluation | Label pairs, tune separately, report holdout and run demo |
| 13–15 | SDE-005 Database | PostgreSQL constraints tested; investigate indexes |
| 16–19 | SDE-006 Queue and API | Real container tests, duplicate and quarantine verified |
| 20–22 | SDE-007 Operations | Logs, Grafana and load results captured |
| 23–26 | SDE-008 Reliability | Two controlled incidents, fix defects, coverage target |
| 27–30 | SDE-009 Portfolio | Honest README, demo video, resume and interview stories |

For every ticket: create issue, branch, test, self-review, commit and PR. Generated baseline already implements much of the code, but your work is validation, understanding, fixes and measurement. Do not backdate or invent development history.
