# Phase C data workflow

Keep the downloaded charity TSV, company API cache, canonical CSVs, truth labels and error examples outside Git. Use `CH_API_KEY` in the process environment; never include it in a command, file, Docker configuration or output. Use only one downloader at a time. The client caches successful minimal responses and 404 results in SQLite, limits requests to roughly 80/minute, backs off on 429 and transient errors, and resumes from cache. A cached 404 is a retrieval failure for that snapshot, not evidence of a nonexistent business. Use a new cache for a future refresh.

Sources: Charity Commission for England and Wales full register download (https://register-of-charities.charitycommission.gov.uk/en/register/full-register-download), Companies House Public Data API (https://developer.company-information.service.gov.uk/). Check current licence terms and exceptions before redistribution; do not publish individual contact details. Retain source dates and aggregate results only.

From the repository root, run `python -m scripts.convert_charity SOURCE OUT --limit 500`, then `python -m scripts.fetch_companies OUT --cache CACHE --distractor-locations 100`. Use a separate output directory for the full sample and reuse the private cache. Candidate IDs are company numbers, but query identifiers are hashed charity organisation IDs, and the matcher receives only id, name, address and postcode. The truth file remains outside the service. The fetcher excludes all sampled true IDs from its distractor additions and filters postcode search results to exact normalized postcode. Other companies are non-reference candidates, not verified unrelated legal entities.

Use `python -m scripts.evaluate_charity OUT tune`, freeze the threshold and then `python -m scripts.evaluate_charity OUT holdout`. One charity per unique company prevents duplicate identity leakage. The split is 60/40, seeded, with the first 500 pilot rows reserved for tuning when the full sample exceeds 1000; weights stay fixed and only the threshold is tuned. The offline tuned threshold does not silently change the worker's default threshold 90. The exhaustive baseline uses the same score and tuned threshold without blocking. Retrieval failures remain false negatives in unconditional recall. Confidence intervals use query-level bootstrap conditional on the fixed pool. Stress results use seeded corruption of held-out records and are reported separately.

Use a fresh Compose project name per immutable snapshot, stop the previous stack first to avoid port conflicts, and copy only canonical companies/charities CSVs into the API container. Do not delete existing volumes or reimport changed data into the same snapshot; reconciliation is later work. `src.ingest` retains two positional arguments. The legacy `fsa_id` database/API field stores a query record ID for compatibility; `charity:` IDs distinguish charity records. No schema-breaking rename is required. Original demo CSVs remain fictional fixtures.

Inspect 30–50 private errors (or all if fewer), document aggregate causes and uncertainties. The report generator writes aggregate results only; manually complete error analysis. Preserve the original synthetic Phase B evidence. Do not claim population accuracy or independent nationwide retrieval.
